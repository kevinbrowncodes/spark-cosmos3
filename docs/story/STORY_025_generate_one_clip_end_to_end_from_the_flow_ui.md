# STORY_025 — Generate one clip end to end from the Flow UI

**Epic:** EPIC_002 — A browser UI for generating and extending clips
**Depends on:** STORY_024 (settings the gateway accepts)
**Unblocks:** STORY_026 (Extend)

As someone using the Flow UI, I want to attach a still, type a beat, press
Generate, watch the bar move and play the finished clip in its tile — and
know that a finished clip is safe on disk even if the engine restarts before
I come back to it.

## Acceptance Criteria

- [x] A job that polls as `done` has its MP4 **downloaded into `/media/flow-outputs` during that poll**, not on first view — a finished clip survives an engine restart (vLLM-omni forgets every job when it restarts, and `/jobs/{id}/content` then 404s)
- [x] Caching is idempotent and failure-tolerant: a second poll does not re-download; a failed download leaves no `.part` file and the lazy path (`media_path`) still works as a fallback
- [x] `flow-conformance http://localhost:8003 --generate --reference <still> --timeout 3600` passes on the box at the UI defaults (720x1280, Length 8 → 193 frames, 35 steps, sound, gemma upsample): the job reaches `done`, progress moved while running, the output is served `FULL` and as an `image/*` `THUMBNAIL`, width/height are reported — 2026-09-08 00:14, job `video_gen_517717db…` at 720x1280, 32/32 checks (`docs/evidence/STORY_025/conformance-generate.txt`); the tool's own 60 s HTTP timeout had to be raised first (flow BUG-002)
- [x] A clip is generated by driving the real UI in a browser (upload the still, type a prompt, press Generate) and its tile plays the finished MP4; screenshots of the running and finished tile are captured as evidence — job `video_gen_95480fff679…`, done in 1867 s, served 720x1280 / 193 frames / 8.04 s / AAC, tile progress moved live from 0 to 92 %; `docs/evidence/STORY_025/01-composed.png` … `04-done.png`
- [x] `docs/api.md` gains a short *Flow UI* note (port, protocol, which gateway routes the sidecar uses, the caching rule) and the README's Flow section points at it
- [x] `flow/` stays ≥ 95 % line coverage; `gateway/server.py` untouched

## Technical Notes

**Cache on completion.** `Cosmos3Gateway.job()` maps status; when the mapped
status is `done` and `flow-outputs/<id>.mp4` is absent, call `_fetch_output`
right there. The download is a few seconds over the compose network; the poll
that reports `done` returns a little late once, and never again. `media_path`
keeps its lazy fetch as the fallback for a cache that was wiped by hand.

**The gemma upsampler runs on the host.** `upsample=true` (the default) makes
the gateway load `gemma4:26b` via Ollama on the host (18 GB), rewrite the
prompt, then evict (STORY_022). If Ollama is unreachable the gateway falls
back to the prose prompt and reports `upsample_fallback_reason`; the render
still completes. Check `curl localhost:11434/api/tags` before the run and
record which path the E2E clip took.

**Memory before the render.** `free -h` must show ≥ 20 GiB available on top
of the resident engine so gemma can load; otherwise the render still runs on
the prose path.

**Two renders, ~90 GPU-minutes.** Conformance first (its report is the
acceptance evidence and it exercises exactly the requests the UI sends), then
the browser-driven clip. Both at the UI defaults, so both ~44 min. Per the
2026-09-06 decision: check the box is idle, then go — no per-render prompt.

**Driving the UI without a person.** Playwright (Chromium, headless) against
`http://localhost:8003/ui/`: attach the still through the asset picker,
type the prompt, press Generate, screenshot the running tile (progress bar),
wait, screenshot the finished tile. Batches live in the browser's
localStorage, so the conformance clip will *not* show as a tile — it does show
in the picker's asset list, which is the protocol-level check.

**No engine logs (BUG_004).** The `docker logs cosmos3-api --since 10m` idle
guard is blind; use the gateway instead: the newest entry in
`data/logs/jobs` and `GET :8002/jobs/{id}` for that id.

## Testing Plan

- **Unit**: `_cache_if_done` helper — done + absent → fetches once; done + present → no call; running → no call; fetch failure → `Job` still returned, no `.part`.
- **Integration**: `/flow/jobs/{id}` on a `completed` job triggers exactly one `GET /jobs/{id}/content` (respx call count), the file lands in `flow-outputs`, a second poll makes no upstream call, and `GET /flow/media/out:{id}.mp4` serves it without touching upstream; upstream content 404 during the poll → job still `done`, media 404 later.
- **Contract**: unchanged shape — `contract.sh` still green.
- **E2E**: the two renders above, with the conformance report and the two screenshots saved under `docs/evidence/STORY_025/` (small PNGs, well under 1 MB each).
- **Coverage**: `--cov=flow --cov-fail-under=95`.

## Estimated Complexity

**Small code, long wall-clock.** ~15 lines in `flow/gateway.py`; the time is
